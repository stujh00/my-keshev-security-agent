# 케셰브(KESHEV) 5일차 — 처음 사용하는 사람을 위한 실행 안내

> 작성 기준: 2026-11-03 (한국 시간). 기존 22단계 문서와 제공 문서는 그대로 보존합니다. 이 안내는 **포장 없이 Windows PC의 프로젝트 폴더에서 실행**하기 위한 것입니다. 설치 프로그램이나 자동 배포를 만들지 않습니다.

## 1. 이 앱에서 볼 수 있는 것

케셰브는 ZTNA·XDR 기능을 보여 주는 로컬 앱입니다. **로컬 서버 실행 성공은 SDP·에이전트 연결 성공을 뜻하지 않습니다.** 실제 연결이 없는 환경에서는 로그인·기기·세션·XDR 정보에 `연결 없음` 또는 `확인 불가`가 나오는 것이 정상적인 실패 표시입니다. 예제(demo) 데이터는 실제 조회 결과가 아닙니다.

추가된 학생 기능:

- **보호 현황:** 사용자·기기·세션 보안 상태와 별도 **PC 실측 JSON** 카드(CPU·메모리·C: 디스크).
- **보안 기록:** 제공된 접속·XDR 기록과 별도 **Windows 실측 JSON** 카드(네트워크 링크·방화벽 프로필·System/Application 경고·오류).
- JSON은 사용자가 파일 선택으로 읽습니다. **실시간 모니터링 또는 자동 재측정이 아닙니다.** 수집 시각과 데이터 출처를 반드시 확인합니다.

## 2. 준비물

- Windows PowerShell, Node.js, 웹 브라우저.
- 사용자의 시험 PC에서는 `node -v` 결과 **v24.21.0**으로 실행되었습니다. 수업 제공 기준은 **v24.19.0**이며, 이 두 버전은 구분해 기록합니다. 다른 버전에서도 같은 결과가 난다고 보증하지 않습니다.
- 원본 프로젝트 폴더: `C:\Users\User\AppData\Local\ALEPH\Workbench\projects\케셰브-방어전` (원래 시험 PC 기준). 다른 PC에서는 본인에게 맞는 경로를 사용합니다.
- 소스 저장소: `https://github.com/stujh00/my-keshev-security-agent`
- 기존 인증·Native Host 설정은 **GitHub에 포함되지 않습니다.** 다른 PC로 토큰·개인키·`native.json`을 복사하지 말고, 제공된 공식 연결 절차와 권한 승인 규칙을 따릅니다.

## 3. 기존 PC에서 실행하기

**첫째, PowerShell을 열고 앱 폴더로 이동합니다.** 아래는 실제 시험 PC에서 사용한 경로입니다.

```powershell
cd "C:\Users\User\AppData\Local\ALEPH\Workbench\projects\케셰브-방어전\on-client"
node -v
```

**둘째, 연결 설정 없이 로컬 화면만 확인**할 경우 다음을 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5189 -NoNativeHost
```

**승인된 Native Host 설정이 이미 있는 기존 PC**에서는 아래처럼 실행할 수 있습니다. 경로가 없으면 이 명령을 무조건 실행하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NativeHostConfig "C:\Users\User\AppData\Local\ALEPH\KeshevNativeHost\native.json"
```

두 명령 중 **하나만 선택**합니다. 포트 5189를 다른 프로세스가 사용 중이면 중복 실행하지 않습니다. 실행 화면에 `케셰브가 켜졌습니다`가 나타나면 **PowerShell 창을 유지한 채** Chrome 등에서 `http://127.0.0.1:5189/`를 엽니다. 실제 로그인/SDP 연결 상태는 앱 화면에서 별도로 확인해야 합니다.

**종료:** 서버를 실행한 PowerShell 창에서 `Ctrl+C`. **재실행:** 같은 폴더에서 위 시작 명령을 다시 입력하고 브라우저를 새로고침합니다.

## 4. 처음 실행 후 확인 순서

1. Chrome 주소가 `http://127.0.0.1:5189/`인지 확인합니다.
2. **보호 현황**을 열어 `보안 상태 요약 · SDP 연결` 카드가 표시되는지 확인합니다. `연결 없음`을 `정상`으로 취급하지 않습니다.
3. 아래 **내 PC 상태 · 측정 기록**에서 `새 PC 측정 JSON 파일 선택`으로 **본인이 실제로 측정한 파일**을 엽니다. CPU·메모리·디스크와 **수집 시각**을 확인합니다.
4. **보안 기록**에서 `내 PC 연결·Windows 기록 · 측정 기록`의 새 파일 선택으로 연결·방화벽·이벤트 기록 JSON을 불러옵니다.
5. Windows **이벤트 로그 수**와 **XDR 보안 사건 수**는 다른 데이터입니다. 네트워크 `Up`은 SDP 연결 성공의 증거가 아닙니다.
6. 측정 파일이 없거나 읽을 수 없으면 `확인 불가` 또는 읽기 실패 이유가 표시되어야 합니다. 잘못된 파일에서 임의의 정상값을 보여 주면 안 됩니다.

### 실측 JSON 파일을 다시 만들 때

2일차 측정용 PowerShell 스크립트 `measure_keshev_pc.ps1`, 3일차 측정용 `measure_keshev_connection.ps1`은 시험 PC의 `Downloads`에서 실행했던 **별도 사용자 스크립트**입니다. **Git 저장소에 동봉되어 있다고 가정하지 마세요.** 해당 파일이 있는 경우 다음처럼 다시 측정합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\Downloads\measure_keshev_pc.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\Downloads\measure_keshev_connection.ps1"
```

측정으로 생성된 **새 JSON 파일 경로를 PowerShell 출력에서 확인**한 뒤 각 화면에서 새 파일을 선택하세요. 다른 PC에서 이 스크립트를 받지 못한 경우, 실측 파일 표시의 재현에는 별도 스크립트 제공 및 실행 권한 확인이 필요합니다. 예제 파일이나 다른 사람이 측정한 기록을 **자기 PC의 현재 실측값**으로 표시하면 안 됩니다. JSON에는 PC 식별 정보가 포함될 수 있으므로 제출·공유 전 내용 확인이 필요합니다.

## 5. 자주 막히는 곳과 해결 방법

| 증상 | 확인 방법 | 다음 행동 |
|---|---|---|
| PowerShell이 폴더 경로를 명령이라고 오류 표시 | `cd` 없이 경로만 입력했는지 확인 | `cd "...\on-client"`처럼 `cd`를 붙입니다 |
| 실행 스크립트를 찾을 수 없음 | 현재 경로와 `Test-Path .\tools\start-alekov.ps1` 확인 | 실제 프로젝트의 `on-client` 폴더로 이동합니다 |
| Node.js 버전 경고 | `node -v` 확인 | 제공 기준 v24.19.0과 현재 버전을 기록하고 호환성을 별도 검증합니다 |
| 브라우저 페이지 접속 불가 | 시작 창에 `켜졌습니다` 메시지가 있는지, 주소·포트가 일치하는지 확인 | 서버를 시작하고 `127.0.0.1:5189`를 다시 엽니다 |
| `연결 없음`, `ENGINE_NOT_CONNECTED` | 로컬 화면과 외부 SDP·에이전트 상태 구분 | 연결 성공으로 주장하지 말고 제공된 연결 안내에 따라 승인된 설정을 점검합니다 |
| PC 또는 Windows 측정 파일이 보이지 않음 | 새 파일 선택과 정확한 JSON 종류 확인 | 측정 스크립트를 다시 실행하고 출력된 새 파일을 선택합니다 |
| `읽기 실패` 또는 `확인 불가` | 측정 파일의 종류·형식·수집 시각·권한 확인 | 데이터를 임의로 수정하지 말고 새로 측정하여 다시 선택합니다 |
| 측정 수치가 과거 값 | 화면의 `수집 시각` 확인 | 새로 측정하여 최신 JSON을 직접 선택합니다 |

문제 진단 시 **비밀번호, 토큰, 개인키, `native.json` 내용은 캡처하거나 공유하지 않습니다.** 관리자 권한이 없다는 이유로 Windows 보안 설정을 끄지 않습니다.

## 6. 5일차 재현 확인 기록

| 항목 | 확인된 근거 | 상태 |
|---|---|---|
| 기존 프로젝트에서 재실행 | 학생이 `start-alekov.ps1 -NativeHostConfig ...` PowerShell 실행 로그 제공 | 확인됨 |
| 로컬 서버 응답 | `http://127.0.0.1:5189` 서버 실행 메시지 | 확인됨 |
| 브라우저 화면 | 보호 현황·보안 카드가 보이는 Chrome 스크린샷 | 확인됨 |
| 기존 SDP·에이전트 실연동 | 브라우저에 `연결 없음` 표시 | **성공 미확인** |
| 독립적인 다른 사람/다른 PC가 문서만 보고 실행 | 아직 결과를 받지 않음 | **미검증** |
| 다른 PC에서 CPU·방화벽·이벤트 실측 재현 | 별도 측정 스크립트·권한·환경 필요 | **미검증** |

5일차의 **타인 재현 검증은 아직 완료가 아닙니다.** 다른 사람이 안내서만 보고 실행하면 다음 내용을 기록합니다: 테스트 날짜, Windows/Node 버전, 기존/새 PC 여부, 실행 명령, 서버 실행 결과, 브라우저 결과, 실제 막힌 단계, 문서 수정 내용, 재시험 결과. 타인의 검증이 어려우면 **동일 PC의 재실행만 확인**했다고 명시합니다.
